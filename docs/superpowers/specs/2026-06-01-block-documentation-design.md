# Block Documentation System — Design Spec

**Date:** 2026-06-01  
**Status:** Approved  
**Scope:** Layout Blocks (`src/blocks/`), Globals (`src/Header/`, `src/Footer/`), Lexical Blocks

---

## Overview

A per-block documentation system that:
- Lives alongside the code (no separate docs folder)
- Is generated and maintained by agents via a `/document-block` skill
- Tracks quality via a checklist with % completeness
- Feeds into a consolidated client delivery document

## `_template.md` Structure

Every `README.md` follows this template exactly. Sections:

1. **Name + Description** — what it does, when to use it
2. **Admin Location** — exact path in Payload admin panel
3. **Fields Table** — name, type, required, localized, description
4. **Variants** — table of available variants (if any)
5. **Screenshots** — desktop (1280px) + mobile (375px) inline
6. **Quality Checklist** — with completeness score (X/20, X%)
   - Accessibility AAA (5 items)
   - HTML Semantics (3 items)
   - Performance (3 items)
   - SEO / AIO / GEO (3 items)
   - Delivery (4 items: tests added, fields documented, screenshots current, delivery notes written)
7. **Schema.org** — applicable type, implemented status, JSON snippet
8. **Delivery Notes** — non-technical instructions for the client

---

## Quality Checklist Items (20 total)

### Accessibility AAA (5)
- [ ] Contrast ratio minimum 7:1
- [ ] All interactive elements keyboard navigable
- [ ] ARIA labels on elements without visible text
- [ ] Correct HTML landmarks (`header`, `main`, `nav`, `section`, etc.)
- [ ] Focus visible on all interactive elements

### HTML Semantics (3)
- [ ] Correct heading hierarchy (no skipped levels)
- [ ] Semantic elements used (`article`, `section`, `aside`, not `div` soup)
- [ ] Images have descriptive `alt` text

### Performance (3)
- [ ] Images use `next/image` with correct sizes
- [ ] No Cumulative Layout Shift (CLS)
- [ ] Off-viewport content lazy loaded

### SEO / AIO / GEO (3)
- [ ] Content directly answers questions (GEO-ready)
- [ ] Schema.org implemented (see section below)
- [ ] Does not block indexing

### Delivery (4 — agent checkable + manual)
- [ ] Unit tests added
- [ ] All fields documented in table
- [ ] Screenshots up to date
- [ ] Delivery notes written in non-technical language

---

## Completeness Score

Calculated as: `checked_items / 20 * 100`

Displayed as: `**Completeness: X/20 (X%)**`

- **100%** → ready for client delivery
- **<80%** → not shippable

## `src/blocks/CLAUDE.md` — Agent Guide

Content:
- When to document (new block, field edit, block finalized)
- Step-by-step process (copy template → fill sections → screenshots → checklist → update consolidado)
- Screenshot instructions (viewport sizes, use real seed data)
- How to calculate completeness score
- Note: applies also to Globals in `src/Header/` and `src/Footer/`

## `src/Header/CLAUDE.md` and `src/Footer/CLAUDE.md`

Shorter files. Reference `src/blocks/_template.md` and `src/blocks/CLAUDE.md` as the canonical source. Only add Header/Footer-specific notes (e.g., admin path is `Globals → Header`).

## `/document-block` Skill — Agent Workflow

1. Read `Component.tsx` + `config.ts` of the target block
2. Copy `src/blocks/_template.md` → `src/blocks/<Name>/README.md`
3. Auto-fill from code:
   - Description (inferred from config labels + component)
   - Fields table (from config.ts field definitions)
   - Variants (from config or component props)
   - Admin location (from config slug + type: Global or Layout Block)
4. Open site with Chrome MCP
5. Navigate to the block (using real seed data)
6. Screenshot desktop: viewport 1280x800 → `desktop.png`
7. Screenshot mobile: emulate iPhone 12 (375x812) → `mobile.png`
8. Run automated checklist items:
   - Scan for `next/image` usage
   - Scan for `alt` attributes
   - Scan for landmark elements
   - Check for Schema.org JSON-LD
9. Calculate completeness score
10. Update consolidated doc at `docs/blocks/README.md`

Agent marks auto-verifiable items `[x]`, leaves manual items `[ ]` for developer review.
