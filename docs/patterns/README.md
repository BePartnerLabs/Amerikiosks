# Patterns

Things this project learned the hard way, one file per topic.

**Why separate files:** so only the relevant one gets read. A single long
conventions document is either skimmed or ignored; a linked file is opened when
its topic comes up.

**What belongs here:** a pattern or antipattern that cost someone real time, where
the reason is not obvious from the code. Each file states what to do, what not to
do, and — crucially — the incident that motivated it. A rule without its story
gets deleted by the next person who finds it inconvenient.

**What does not:** anything already enforced by a tool. If Biome, a GritQL plugin
in `biome-plugins/`, or a `scripts/validate-*.mjs` can catch it, the enforcement
is the documentation. Write the rule here only when automation is impossible or
when the *why* still needs explaining alongside it.
